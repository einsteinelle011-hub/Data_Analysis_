数据库连接池耗尽问题分析

1. 典型现象
- 应用线程明显变多但都在等待数据库连接；
- 数据库本身负载不高；
- 应用日志中出现获取连接超时的异常。

2. 常见原因
- 连接池最大连接数设置过小，无法覆盖高峰期请求量；
- 存在忘记 close() 的代码，导致连接长期被占用；
- 某些慢 SQL 导致连接占用时间过长；
- 应用启动了多个连接池实例，实际总连接数超过数据库承载能力。

3. 排查方法
- 打开连接池的监控/日志，查看当前活跃连接、空闲连接、等待队列长度；
- 在数据库侧查看当前会话，确认是否都是来自同一应用；
- 检查慢 SQL 日志，确认是否有单条语句长期不返回。

4. 修复建议
- 按 QPS 和单次业务耗时重新估算连接池大小；
- 保证所有获取的连接都在 finally 中关闭；
- 给慢 SQL 建索引或分库分表；
- 必要时在入口做限流，避免瞬时请求把池子打满。
